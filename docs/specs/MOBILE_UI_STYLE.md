# Mobile UI Style

本文件定义 Study For Read Phone 首版移动端视觉和交互规格。后续 Flutter 任务必须优先遵守本文件，再参考 `UI_FLOWS.md`。

## 1. Design Direction

首版移动端采用：

- 沉浸阅读优先。
- 学习工具贴近阅读出现。
- 统计和复习入口清晰，但不抢阅读器空间。
- 可借鉴 Linga 这类阅读学习产品的闭环：真实内容阅读、点词、收藏、复习、统计。
- 不照搬旧项目网页端布局。

移动端不是网页端缩小版。禁止把桌面网页的多栏布局、密集卡片、常驻工具栏直接搬到手机阅读器。

## 2. Navigation

登录后主 App 底部导航为：

- 书架
- 词卡
- 统计
- 设置

首版没有“阅读”Tab。

阅读入口来自：

- 书架里的书籍条目。
- 书架顶部“继续阅读”区域。

Reader 是独立全屏路由。进入 Reader 后，不显示主 App 底部导航。

## 3. Visual Tone

整体风格：

- 安静、克制、适合长时间阅读。
- 主色使用低饱和绿色或蓝绿色。
- 背景优先使用接近纸张的暖白。
- 学习状态、同步状态、统计数字可以用轻量色块，但不能压过正文。

避免：

- 大面积高饱和渐变。
- 过多装饰卡片。
- 网页式顶部大标题长期占据阅读空间。
- 阅读器里常驻底部 App 导航。

## 4. Typography

阅读正文：

- 日文正文优先使用适合长文阅读的衬线字体或系统日文字体。
- 中文译文优先使用清晰中文阅读字体。
- 正文字号首版默认中等偏大，用户可在 Reader 控制层调整。
- 行高必须宽松，优先保证长文舒适度。

词典和工具 UI：

- 使用系统 sans-serif。
- 信息密度要比阅读正文高，但不能拥挤。

假名注音：

- 日语词条和正文注音使用 ruby 或等效视觉结构。
- 注音必须小于正文，并使用低饱和辅助色。
- 注音不能导致行距剧烈跳动。

## 5. Library Screen

书架必须支持：

- 空书架状态。
- 导入入口。
- 继续阅读入口。
- 本机书籍列表。
- 每本书的同步状态。

书籍状态文案必须明确：

- 本机书籍。
- 离线可读。
- 进度已同步。
- 待同步进度。

禁止暗示云端书柜或云端原书存储。

## 6. Reader Default State

Reader 默认状态是全屏阅读。

默认隐藏：

- 顶部书名/章节栏。
- 字体设置按钮。
- 上一章/下一章按钮。
- 翻译段落控制。
- 主 App 底部导航。

默认显示：

- 正文。
- 极淡的段尾翻译热区。
- 必要时显示很轻的离线/同步提示。

点击正文空白区域时，切换 Reader 控制层显示或隐藏。

## 7. Reader Control Overlay

点击空白区域后出现控制层。

顶部控制层：

- 返回。
- 书名和章节名。
- 离线/同步状态。
- 字体设置。

底部控制层：

- 左侧：上一章。
- 中间：翻译段落或当前阅读进度控制。
- 右侧：下一章。
- 阅读进度条。

控制层是临时浮层，不是页面常驻结构。

## 8. Paragraph Translation

段落翻译不是新页面，也不是 bottom sheet。

触发方式：

- 每个段落最后一个标点或最后一个词后面有一个极淡的 `+` 热区。
- `+` 要淡到几乎不影响阅读。
- `+` 位置要靠近段尾标点，略向左贴近正文。
- 所有状态下符号都保持 `+`，不能变成 `...`、`✓` 或其他图标。

点击 `+` 后：

1. 直接请求翻译当前段落。
2. 不显示“翻译本段 / 复制 / 保存句卡”菜单。
3. 不显示二次确认。
4. 翻译中只用轻量状态提示，不改变 `+` 符号。
5. 翻译完成后，在原段落下方插入一个译文段落。
6. 译文段落样式接近正文，只用颜色轻微区分。
7. 译文段落下方不显示“复制译文 / 保存私有句卡 / 收起”按钮。

规则：

- 每次只发送当前段落。
- 不发送整章。
- 不发送整本书。
- 译文可以本地缓存。
- 离线时点击 `+` 显示轻量离线状态，不离开阅读器。

## 9. Lookup Bottom Sheet

点词或短语后打开词典底栏。

内容必须包含：

- 词面。
- 假名读音。
- 词性。
- 简短释义。
- 完整释义入口或展开区域。
- 小喇叭读音按钮。
- 加入词卡按钮。
- 例句入口。

小喇叭规则：

- 日语词条必须提供读音按钮。
- 首版可先使用系统 TTS。
- 如果后续接入音频供应商，接口和任务卡必须单独定义。

点词底栏不能显示主 App 底部导航。

## 10. Vocabulary And Review

词卡页首版包含：

- Due。
- All。
- Private Sentences。

复习页保持简洁：

- 显示词面。
- 显示假名读音。
- 显示释义。
- 显示“不熟”和“认识”两个主操作。
- 离线可复习。

复习页不需要复杂统计图，不需要网页式大卡片堆叠。

## 11. Anki Export

词卡功能需要支持导出到 Anki。

参考：`https://docs.ankiweb.net/importing/text-files.html`

首版只做本地导出，不做 AnkiWeb 登录和自动同步。

导出入口：

- 放在词卡列表或设置中的“导出到 Anki”入口。
- App UI 只展示导出范围、选项和完成状态。
- App UI 不展示完整导出文件预览。

导出格式：

- 文件扩展名：`.txt`
- 编码：UTF-8
- 分隔符：Tab
- HTML：允许 HTML 字段
- 第一字段：稳定 `id`，用于 Anki 识别重复和更新

建议文件头：

```text
#separator:Tab
#html:true
#deck:StudyForRead::Japanese
#notetype:StudyForRead Japanese
#columns:id	front	reading	meaning	example	source	tags	audio
```

字段：

- `id`：稳定词卡 ID。
- `front`：词面，例如 `長い`。
- `reading`：假名，例如 `ながい`。
- `meaning`：中文释义。
- `example`：例句，可选。
- `source`：来源书籍和章节，可选。
- `tags`：标签，例如 `ja zh adjective`。
- `audio`：可选音频引用，例如 `[sound:nagai.mp3]`。

媒体规则：

- 如果导出音频字段，文件内容只引用 `[sound:filename]`。
- 音频文件如何生成、保存、分享必须在后续任务卡里单独定义。
- 首版可以不导出真实音频文件，只预留字段。

## 12. Stats

统计页首版只做基础学习反馈：

- 今日阅读分钟。
- 近 7 天阅读分钟。
- 点词次数。
- 段落翻译次数。
- 新增词卡数。
- 复习词卡数。

统计页要清楚，但不能变成主要首页。

## 13. Settings

设置页首版包含：

- 源语言。
- 目标语言。
- 字体大小。
- 阅读主题。
- 同步状态。
- 导出到 Anki。
- 退出登录。

后续再考虑：

- 翻译供应商偏好。
- 数据导出。
- 账号删除。
- 隐私控制。

## 14. Accessibility And States

必须覆盖：

- Loading。
- Empty。
- Offline。
- Sync pending。
- Sync failed。
- Provider unavailable。
- Import failed。

交互热区必须足够可点，但视觉上可以很淡。

任何错误提示都不能泄露：

- 原书全文。
- 章节全文。
- token。
- 原始翻译日志。

## 15. Implementation Boundary

移动端 UI 任务不得：

- 上传原书。
- 上传章节。
- 在服务端保存译文段落。
- 实现全书翻译。
- 实现云端书柜。
- 实现支付或订阅。
- 直接复制旧项目网页端 UI。
